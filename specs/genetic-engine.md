# Pip genetic-content and engine proof

Status: owner-approved bounded contract for a reversible host proof. The [executable proof and generated report](../prototype/genetics/README.md) implement one pinned qualitative Pip fixture; detailed content remains provisional. Pip is the accepted qualitative worked reference in [genetics](genetics.md#pip-accepted-worked-phenotype-reference). The five information layers and eleven dimension families remain authoritative. This contract neither selects final species art/balance nor represents a complete production game engine.

## Outcome and boundary

Generate a small family of internally valid genomes, explain the resulting qualitative phenotypes and inherit one offspring genome from compatible parents. Feed the same facts into a research knowledge view that preserves unknown, carried and expressed distinctions. This is the minimum foundation needed by the collection/workbench design; it is not a library-management platform.

Use one versioned Pip content package. Reuse the project's existing host runtime for a small module and fixture report. No new service, UI framework, database, schema language, solver dependency, paid API integration, image generation or device firmware is needed. The LLM contribution is offline draft content reviewed before it becomes input; the proof makes no model calls.

## Records crossing the boundary

| Record | Required meaning |
| --- | --- |
| Content package | Stable package/version; applicable class/body plan; baseline modules, locus definitions, permitted expression operators, compatibility, reference context, required-fact manifest and known exclusions |
| Locus definition | Stable ID/version; allowed alleles; copy scheme; applicability and inherited dependencies; expression contributors; affected dimensions; research-fact references; worked valid/invalid cases |
| Genome candidate | Pinned content identity; complete inherited baseline references and allele copies; source kind and provenance; no player/individual identity allocated |
| Founder support | Explicit eligible full candidates or authored allowed choices with constraints for this sample; separate from the player's current knowledge |
| Expression context | Versioned maturity/medium/reference conditions. Unsupported contexts yield an explicit unsupported result, never silent adult defaults |
| Phenotype | Qualitative dimension values, applicability/unsupported markers, derived capability eligibility and per-output reason traces; no invented quantitative performance |
| Research knowledge | Player/sample/candidate scope, retained findings and established facts. Unknown markers belong here, never in a supposedly complete genome |
| Inheritance result | Exact parental genome references, per-copy donor choices, resulting candidate and validity result. It is not a saved birth or ownership grant |

Saved individual identity, resource transactions, consent, creation acceptance and exact preserved assets remain outside this pure engine, under [sample-to-critter](sample-to-critter-contract.md). Draft candidates cannot spend inventory, complete a research record or create a living individual.

## Small callable operations

These describe responsibilities, not a required public API/service topology.

1. **Validate content:** check unique IDs/versions, known references, copy/allele definitions, applicability, complete baseline coverage, valid operators and acyclic expression dependencies. Return structured errors with a source path; do not guess replacements.
2. **Construct founder candidates:** use validated content and explicit authored support/selection inputs. Enumerate permitted candidates for coverage or use a pinned sampling policy and random-choice source for a batch. Never broaden the sample's supported set to fill a batch request.
3. **Validate genome:** verify copies/alleles, baseline compatibility, required inherited contributors and declared constraints. Return valid/invalid/unsupported distinctly. No mutation or silent repair.
4. **Express:** resolve baseline and allele effects in dependency order under the declared context; derive capabilities only after their structures/requirements are known. Return phenotype plus explanations identifying relevant sources and rules. This operation has no random expression roll in the Pip proof.
5. **Inherit:** check the proof's compatibility, choose one copy from each parent at every two-copy locus, retain donor trace, validate the resulting candidate and express it. Do not redraw until a desirable child appears or repair an invalid child by inserting unrelated alleles.
6. **Project research knowledge:** expose only established hereditary facts and conclusions justified by them. A partial markings result can show one known p and unresolved appearance without exposing the full candidate's other copy. Fully known Pp can show pale variant carried and no pale markings under the applicable rule.

Caller-selected authored fixture choices are sufficient for the first worked cross. If a seeded sampling implementation is added, pin the PRNG and algorithm version and preserve exact results. A seed alone does not preserve an individual across content changes. Founder weights and independence in the proof are illustrative, not approved population balance.

## Baseline and locus content

The baseline supplies Pip properties through explicit versioned sources, not untraceable fields pasted into a phenotype. Fixed inherited module references travel with a candidate/offspring; class membership constrains compatibility and does not reroll a fresh class average at birth. Variable loci C, R, P, M and E control only their declared effects. All definitions below are provisional proof content, not a final biological model.

Class compatibility fixes the six-legged, flexible-bodied terrestrial plan. The candidate carries a pinned baseline module set; both parents in this proof have that same set. Coat, underside and eyes additionally have explicit fixed two-copy variants: charcoal/charcoal, cream/cream and amber/amber. Other baseline modules are inherited unchanged as versioned references; their internal loci are not modeled. This tests composition and provenance without pretending to have decoded a universal genome. A future varying module requires an explicit inheritance rule before crossing it.

| Dimension family | Source and qualitative contribution | Boundary |
| --- | --- | --- |
| Structure | Class plan: small rounded body, six short jointed legs, gripping claws, flexible covering; C determines optional soft crown frill | No rigid shell or wings |
| Appearance | Fixed coat/underside/eye variants; R controls eye rings, P pale body markings | No final art or palette values |
| Mechanics and movement | Baseline terrestrial walking and low rough-obstacle clambering; M adds short bursts | No flight, specialized swimming or smooth-wall climbing; force/speed unsupported |
| Sensing and signaling | Fixed module: nearby visual motion, surface vibration, quiet chirp; frill display requires crown | Rings confer no sensing bonus; ranges and signal meanings unsupported |
| Cognition and innate tendencies | Fixed module: moderate curiosity, sudden-motion caution, familiar-individual tolerance and simple association-learning capacity | Learned associations and familiarity records are lifetime state |
| Energy and nutrition | Fixed module: plant-derived nutrition, modest stores and rest after repeated bursts; E modifies supported movement cost | Hunger/fatigue are state; amounts/rates unsupported |
| Maintenance and protection | Fixed module: minor surface repair depends on energy/nutrients | No limb regeneration or implicit armor; repair rates unsupported |
| Affinities and exposure response | Fixed module: mild, shaded, moderately humid preference; prolonged heat/dryness adverse | Numeric thresholds unsupported |
| Development and longevity | Fixed module: juvenile smaller, crown less developed if present, lower capacity; adult reference used here | No lifespan or later transformation specified; juvenile simulation unsupported in this proof |
| Reproduction | Same-version compatibility rule, two-copy variable loci and fixed inherited baseline | Fertility, breeding costs and other-class compatibility unresolved |
| Fantastic physiology | Explicit class exclusion: not applicable | No absent-field inference of powers |

Every required qualitative baseline contribution must resolve for this fixture. Numeric unknowns listed above remain unsupported, outside its declared qualitative scope; they cannot be reported as measured or fully simulated. Reference context is a healthy, rested adult on firm ground in mild conditions. The five information layers remain separate: class constraints, inherited data, expression rules/context, resolved phenotype, and lifetime state/history.

| Variable locus | Allowed copies and expression rule | Dependencies |
| --- | --- | --- |
| `form.crown` | C/C or C/c: crown; c/c: none | Frill display requires crown |
| `appearance.rings` | R/R or R/r: pale eye rings; r/r: plain amber eyes | Fixed eye baseline; no sensory effect |
| `appearance.markings` | p/p: pale body markings; P/P or P/p: none | P/p carries p without faint expression |
| `movement.drive` | M/M or M/m: short bursts supported; m/m: steady movement only | Terrestrial plan; burst has greater peak demand, no numeric magnitude |
| `movement.efficiency` | E/E or E/e: less energy than e/e for the same supported locomotor action | Compare identical action, maturity, medium and effort; cannot grant a movement mode |

Each locus has two copies and independent assortment in this fixture. Dominance is local to these authored effects; it is not quality, strength or a universal allele convention. A sample's supported founder set is a separate constraint: the 243 combinatorially valid genomes are not automatically all available from every sample. A record with one known p copy and one unknown copy cannot justify choosing between Pp and pp until research establishes the missing information.

## One traced compatible cross

| Input | C | R | P | M | E |
| --- | --- | --- | --- | --- | --- |
| Parent A | Cc | Rr | Pp | Mm | Ee |
| Parent B | cc | Rr | Pp | mm | ee |
| Recorded contribution A | c | r | p | M | E |
| Recorded contribution B | c | R | p | m | e |
| Child candidate | cc | Rr | pp | Mm | Ee |

The child inherits the shared baseline and fixed charcoal/cream/amber variants. In the adult reference context it has no crown or frill display, pale eye rings and pale body markings, and supports bursts with lower energy cost than an otherwise matched Mm/ee individual. Its curiosity, sensing and other fixed contributions retain their source traces. Injuries, training and memories are not inherited.

With equal transmission of either parental copy, this fixture predicts 50/50 crown/no crown, 25/50/25 RR/Rr/rr, 25/50/25 PP/Pp/pp, 50/50 Mm/mm and 50/50 Ee/ee. These are conditional fictional inheritance probabilities, not population balance or guarantees about the next child. The pure operation returns this exact candidate and donor trace. Only the separate game acceptance boundary can allocate a new individual and parent identities; retries of an accepted creation must retain its result, not reroll.

## Validity and disclosure rules

- Unknown knowledge is not a missing/illegal allele. A complete candidate contains valid inherited data even when its research projection is partial.
- Every output has an authored source or an explicit not-applicable/unsupported marker. Unmodeled is never false, zero or decoded.
- Pip's optional crown controls frill-display eligibility: cc must not retain a frill-display ability. Eye rings confer no sensory bonus. E reduces the cost category of supported movement and cannot enable burst movement when M is absent.
- Qualitative tiers can be compared under the same declared context, but cannot be presented as measured speed, energy, longevity or temperature limits. Current condition and learning are outside the inherited genome and do not rewrite it.
- Research completeness is evaluated against the sample's required-fact manifest, including supported configuration choices; neither known phenotype nor all visible tiles establishes full genotype knowledge.
- The proof's ready-for-review result is not authorization to incubate. Live creation still needs complete selected supported genome, rights and inputs accepted by the game boundary.
- The proof uses one compatible class and a fixed shared baseline. Cross-class inheritance, mutations, linkage, developmental transformations, neural behavior and quantitative physiology remain unsupported and are reported as such.

## Acceptance, validation and stopping condition

| Check | Evidence required |
| --- | --- |
| Exact Pip example | Cc/Rr/Pp/Mm/Ee expresses crown, rings, no pale markings, carried p, burst capability and comparatively efficient supported movement; every baseline property has a source |
| Candidate coverage | Enumerate the three unordered genotypes at each of five two-allele loci: 3^5 = 243 genotypes for this fixed compatible fixture. This is coverage, not a uniform population distribution |
| Expression boundaries | cc removes crown/frill display; rr removes rings only; pp expresses pale markings; mm cannot dash even with E; E does not change inherited drive; current fatigue never changes alleles |
| Heredity | One worked cross retains exact parent contributions and expected genotype/phenotype. Small single-locus forecasts match the declared two-copy rules; no Monte Carlo required |
| Invalid inputs | Unknown allele, wrong copy count, missing required baseline, incompatible baseline/class, cyclic rule dependency and unsupported context are rejected/reported without repair |
| Research disclosure | Unknown → one-copy finding → decoded candidate keeps the same source; neither hidden allele nor unjustified phenotype leaks before knowledge supports it |
| Preservation | Same pinned inputs/context resolve the same phenotype; changed content is a new version, never silent alteration of an old result |
| Game relevance | Report contrasts a few individuals and explains a useful appearance, capability or carried-variant difference. Technical validity alone does not establish fun/balance |

Implementation should be one small coherent proof: content fixture, domain module, focused acceptance tests and a readable report. One architecture boundary check, implementation and independent technical/genetics review suffice unless a concrete defect needs correction. Inspect relevant invariants and the bounded genotype space; do not add a broad stress/performance suite or service infrastructure. Stop when the report makes the genotype/phenotype and research links reviewable. Owner decisions concern meaningful content/experience changes, not routine test plumbing.
